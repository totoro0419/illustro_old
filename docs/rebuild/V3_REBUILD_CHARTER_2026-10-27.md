## 2. 保持するものと作り直すもの
### 保持すべき契約と成果
- 一枚絵中心。優先順位：直感的な操作 → 使いやすさ／軽さ → 多機能。
- 既存の承認済みPC/Tablet UI、明るいAurora、Brush設定の意味、筆圧、強制入り抜き、基本ペン・消しゴムの見た目と操作仕様。
- Architecture V2の作品／レイヤー／一筆一履歴／固定256px論理区画／疎な画像データ／Undo/Redo分岐／保存・復旧の意味。M01–M47の名称と順序。
- ブラシの計算やプリセットの **外から観察できる合格済み挙動**。既存計算部品の流用は、新ランタイムと分離でき、機能と性能を検証できる場合に限定する。
- ユーザーの既存作品と保存形式。新アプリの正式切替より前に、旧データの読み込み・無破壊移行・復旧・書き出しを検証する。元データは上書きしない。
### 新規実装するもの
- 画面全体の指・ペン入力受付、ペンと指を別々に管理する状態機械。
- キャンバス移動・拡大・回転の表示制御。
- 仮線／正式画像を一つの表示空間で扱い、仮線中も一体として移動する表示構造。
- 正式描画を別で進めるための指示・結果の受け渡し。古い仕事の取消、順序、エラー回復を一つの入口で管理。
- UI・レイヤー・Undo・保存と描画の境界。旧デバッグ用の大量の分岐・表示マスク・タイマー継ぎ足しを新基盤へ持ち込まない。

## 3. 絶対条件：入力が最優先
1. **ペンで描いている最中、離した直後、仮線のみの間、正式描画中、本線反映中、保存中** のどこでも指による画面移動・拡大・回転を受け付ける。
2. 指／ペン入力の開始・移動・終了・取消を一元管理。入力受付は正式描画の完了通知や保存完了を待たない。
3. 入力を受け取る側では作品全体のコピー、重いGPU送信、同期的な待機を行わない。表示更新・描画指示は独立した経路へ渡す。ユーザー操作の見た目の更新も待たせない。
4. **確定済み作品・仮線・入力対象領域を同じ位置変換で動かす**。仮線→本線へ切り替えても位置・サイズ・角度を飛ばさず、重複・欠落・黒い四角を出さない。
5. 正式計算を止める／遅らせる試験は追加の防護マスクで隠さず、処理と表示の境界で行う。未確定の入力は作品に保存しない。
6. Web/Androidが指イベントをアプリへ配送しない場合、JavaScriptのみでは受信できない。その場合はWebの制約を明記し、**Androidネイティブの入力経路やアプリ構成**を別候補として比較する。何も実証せずに「ゼロ遅延」を保証しない。

## 4. 新アプリの構造（設計上の責務）
- `Input`: Pointer Events/Touch Eventsを受け、指・ペンの状態と操作の意味を確定する。WorkerやGPU完了を待たない。
- `View`: キャンバスの移動・拡大・回転の値を所有し、表示する確定作品と仮線をまとめて動かす。
- `Stroke`: ペンの軌跡、筆圧、ブラシ設定を扱い、描画中の仮線と正式な一筆の意味を分離する。
- `Raster/Renderer`: 変更領域だけを計算・画像化し、完成した表示データを返す。重い仕事を入力受付へ持ち込まない。WebGL2/WebGPU対応は実機で個別に検証。
- `Document/History`: 一筆一操作、レイヤーへの確定、取り消しとやり直し、整合性を保持する。
- `Storage`: 保存／復元／旧データ移行を独立させる。正式描画やユーザー操作をブロックしない。
- `UI`: 承認済みの見た目と動線を再実装し、各部へ操作を渡す。独自の第2描画経路を持たない。
- 最初は `apps/illustro-v3/` 以下へ独立実装。旧 `apps/editor/` を新アプリから丸ごと読み込まない。

## 5. 再構築工程と合格条件
| 段階 | 実装するもの | 次へ進む条件 |
|---|---|---|
| R0 | 旧機能・保存形式・最新成果を一覧化し、残す仕様を固定。新アプリの独立した起動骨格 | 旧アプリに変更なし／起動する |
| R1 | **実際の指・ペン入力／移動・拡大・回転**の新実装と観測 | 端末上で1・2本指、ペンから指への切替が常に受付可能 |
| R2 | **実際の基本ブラシ + 仮線 + 時間のかかる正式確定処理**を組み込む | ユーザーのAndroid実機で、太い長線→離筆→仮線のまま1・2本指で即座に移動・拡大・回転可能。仮線と作品が一緒に動く |
| R3 | レイヤー・一筆一履歴・確定前Undo/Redo | R2を維持し、連続描画、正しい取消、表示破綻なし |
| R4 | 旧作品の読み込み・保存・復旧・書き出し | 実作品を無破壊で往復。旧データを自動上書きしない |
| R5 | 承認済みUI・色・ブラシ設定等を戻す | 高頻度操作、描画、R2・R3・R4が回帰しない |
| R6 | 全体の実機検査、WebGPU/WebGL2比較、公開切替の準備 | ユーザーが確認して受入。旧公開版を勝手に消さない |

- 上記R0–R6は再構築内部の作業区分であり、既存M01–M47を改番・置換するものではない。
- **R2がAndroidで不合格なら、原因を放置してR3以降に進まない。** Webの受信段階から落ちているならAndroidネイティブ経路の比較も検討する。
- すべての主要段階に固定QA URLを設けるが、Pagesで旧QAを消さない。自動化のPASSと実機の合格は区別する。
- 4000×4000級、太いGペンと鉛筆、長線、連続描画、指1本/2本、仮線→本線の移行、回転・縮尺、Undo/Redo、保存・復元、表示正確性を含める。

## 6. 実行上の禁止事項
- 「GPUが犯人」「Androidが犯人」など、証拠のない断定。
- 同じ旧描画・入力ランタイムを新しい箱に移し替えるだけの再構築。
- R2実機合格前に巨大UI・全機能・保存機構を接続し、原因を追えない状態へ戻すこと。
- 合格済みの作品・ブランチ・固定QAを削除すること。
- 合格していないものを『原因解決』『完成』『実機PASS』と報告すること。
