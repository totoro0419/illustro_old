# M10 — 指入力消失の原因を特定するための未完了作業

**状態：原因未特定。ユーザー実機不合格。修正完了ではない。**

## 1. 確認できた事実

- Android実機で、ペンを離した直後から本線が反映されるまで、指で実際にドラッグ・ピンチしてもキャンバスは動かず、「Touch実数」も0のままだった（ユーザーが実機で確認）。
- PR #64のWindowキャプチャー記録では、ペン離しから本線反映までの約275〜306msの区間に `touchstart` / `pointerdown touch` が記録されない。記録自体が遅延/消失した可能性があり、ユーザーが触っていないことは意味しない。
- 該当区間に長時間のJavaScript停止や保存準備処理の占有は記録されなかった。ただし、ログの測定精度より短い処理や、Android/Chrome内部の遅れまで否定していない。
- PR #63のPC上の疑似タッチ＋人工的なGPU完了保留は実機現象を再現していない。PASSを原因特定・修正完了の証拠としない。

## 2. 争点と一次資料

何が指イベントを失わせるのか：

1. **端末のタッチ検知より前**（タッチパネル制御・ペン近接中の検知抑制）。
2. **Android内**（手のひら/誤接触防止による指イベント破棄）。
3. **Android → Chrome / Chrome内部**（入力配信・ブラウザ処理・画面合成）。
4. **Chrome → Illustro**（DOMイベントの到達先や伝播）。
5. **Illustro内部**（受けたイベントがCanvasNavigationへ伝わらない）。

Android公式一次資料： https://source.android.com/docs/core/interaction/input/touch-devices

公式には、Androidはドライバーから受け取った入力をInputReader→InputDispatcherで処理し、パームリジェクションに該当する入力をアプリへ渡さず破棄する場合がある。ただし **今回その機能が原因だと判明したわけではない**。

## 3. 最小限の実機比較（設定変更を伴わない）

同じ端末・ブラウザー・作品で、次の4ケースを複数回比較する。

| 条件 | 描画 | 次の指操作 | ペンの位置 |
|---|---|---|---|
| A | ペンで太い線 | 直後に1本/2本 | 画面近く |
| B | ペンで太い線 | 直後に1本/2本 | 画面から十分離す |
| C | 指で太い線 | 直後に1本/2本 | ペンを遠ざける |
| D | 線を描かない | 1本/2本の操作 | ペンを画面近くに置く |

- Aでだけ失敗すればペン近接/誤接触防止が有力。ただしそれだけで断定しない。
- A/B/Cすべてで失敗すれば、ペン近接単独説は弱くなり、描画処理・Chrome側の入力配信をさらに疑う。
- **通常のWebページでもペン近接時に指入力が失われるか**を別条件で確認すれば、Illustro固有の経路かを判別しやすい。
- ペンを使用した描画が分かる動画・時刻付きログがあれば採用。接触時刻を確認できない推測は証拠扱いしない。

## 4. 可能であればAndroidの生入力を照合する

PCとAndroid端末をUSBで接続し、端末の開発者用接続を使える場合のみ実行。**特別な設定変更、root化、誤接触防止の無効化は行わない**。

```sh
adb devices
adb shell getevent -lp
adb shell getevent -lt
```

- `getevent -lp` で端末が利用しているタッチ入力機器を確認する。
- `getevent -lt` 実行中に実際のペン操作と指操作を行う。ログ取得を終了するにはターミナルで Ctrl+C。
- WindowsのPowerShell等でファイル保存する場合：`adb shell getevent -lt > illustro-device-events.txt`
- この出力が取れない端末では「タッチパネルの生入力は未確認」とする。取得不能と入力未発生を混同しない。
- ログはタッチ座標や端末の情報を含む場合があるため、公開前に必要部分だけ抽出・匿名化する。

**判定の仕方**

| 生入力（端末側） | Web側の指入力 | 支持される判断 |
|---|---|---|
| 指の接触を示すイベントあり | Window captureにもあり | Illustro内部の操作経路を調査 |
| 指の接触を示すイベントあり | Window captureにはなし | Androidでの抑制またはChrome配信が疑わしい。Android上位の記録を追加 |
| 指の接触を示すイベントなし | Window captureにもなし | タッチパネルの検知/ドライバー段階が疑わしい。ただし機器/イベントの取り違えに注意 |
| 生入力取得不可 | Window captureになし | 原因確定不能。推測で結論を書かない |

重要： `getevent` は基本的にドライバー側の生入力を扱う。生入力が存在しWeb側が欠落しただけでは「AndroidかChromeのどちらか」までは確定しない。Android上位のInputDispatcher/MotionEvent相当の証拠を別途収集する。

## 5. 完了の必須条件

- 実機で入手できない証拠がある間は **未完了** とし、推測で完了・PASSと記さない。
